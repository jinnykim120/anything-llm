Document Expansion LLM — v18 시스템 소개

정책지원팀의 자료 정리·검색·활용을 돕기 위해 만든 사내 문서 아카이브 + AI 질의응답 + 문서 작성 시스템. 위쪽은 무엇을 할 수 있는지 도식으로 소개하고, 가운데는 지금 상태와 한계를, 아래쪽은 기술 아키텍처를 기록한다.

목표 1·2 완료 · 목표 3 확장(전사문서작성tool) 실코퍼스 78문서 · 서버 테스트 568/568 할루시네이션 방지 원칙 — 근거 없으면 "확인 필요" 서버 미확보 · 로컬 PC 한정 운영
00

우리가 만들고자 하는 4단계 · 지금 어디까지 왔나

처음 기획했던 목표는 4단계다. 1·2단계는 완료했고, 3단계(문서 작성)는 두 갈래로 확장 중이다.

✓

1단계 · 자동 분류·적재

문서를 올리면 AI가 종류·업무·분야를 제안하고, 사람이 확인만 하면 자동으로 정리돼 보관된다.

완료
✓

2단계 · 자연어 검색·답변

질문하면 근거를 들어 답한다. 출처 번호를 눌러 바로 검증하고, 필요하면 최신 외부 자료까지 더해 답한다.

완료 + 고도화
●

3단계 · 문서 작성

① 답변 하나를 보고서로 바로 만들기, ② 작년 문서 + 신규 기준으로 올해 문서 전체를 다시 채워 넣기 — 두 가지로 확장.

진행 중
4

4단계 · 모바일·웹 접근

사무실 PC가 아니어도 어디서든 접속해 검색·확인이 가능해지는 단계.

착수 전
01

이 시스템이 할 수 있는 것

지금 시점에서 실제로 쓸 수 있는 기능 전체를 한눈에 정리했다.

📥

업로드만 하면 자동 정리

PDF·워드·엑셀·한글 파일을 가리지 않고 올리면 AI가 업무 분류·문서 종류·분야를 제안한다. 사람이 확인만 하면 태그가 붙은 채로 아카이브에 쌓인다.

🔍

자연어로 질문, 근거로 답변

관련 문서를 찾아 그 내용만으로 답한다. 문서에 없는 내용은 지어내지 않고 "확인 필요"라고 표시한다.

🎯

출처 번호를 눌러 바로 검증

답변 속 [3] 같은 번호가 클릭 가능한 버튼이 된다. 누르면 원문의 정확한 위치가 사이드바에 열린다.

🧵

맥락을 이어가는 후속 질문

"그중 A 부분은…" 같은 후속 질문도 이전 대화를 참고해 정확히 찾아낸다.

🌐

필요하면 외부 최신 자료까지

아카이브에 없을 수 있는 최신 법·규제·동향은 웹 검색으로 보강하고, [브라우징N]으로 구분해 표시한다.

📝

답변을 그 자리에서 보고서로

답변 내용만 쓸지 외부자료로 보강할지, 정리만 할지 시사점·동향·리스크까지 분석할지 — 2축으로 골라 바로 만든다.

🏢

(신규) 전사문서작성tool

작년 문서를 뼈대로 삼아 올해 신규 기준에 맞춰 문서 전체를 절별로 다시 채운다. 부족한 자료는 [자료 필요]로 표시하고 바로 요청서로 뽑는다.

🛡️

사람이 마지막 확인

분류도, 답변도, 초안도 AI가 제안만 하고 최종 확정·수정은 항상 사람이 한다.

02

어떤 도구로 만들었나

개발은 팀원 개인 컴퓨터에서, 아래 도구들을 조합해 진행했다. 가운데 "Orca"가 전체 작업을 조율하고, AI 코딩 에이전트(Claude Code)가 실제 코드 작성·설치·테스트·문서화를 맡는다.

화살표는 "이 도구가 Orca(작업 조율)로 투입되어 함께 쓰인다"는 뜻이다. 오픈소스(AnythingLLM)를 베이스로 포크해 우리 것으로 개조했다 — 처음부터 새로 만들지 않고, 검증된 기반 위에서 아카이브·질의응답·문서작성 기능을 쌓아 올렸다.

04

질문을 던졌을 때 답변이 만들어지는 흐름

아카이브 내부 자료만으로 답하는 기본 흐름이다.

예시 질문 · "2025년 GS리테일의 국수 출하량은? 그중 가장 많은 출하량 제품은 무엇이고, 국수 출하량이 강제되는 이유는 뭐야?"
↓
1
(선택) 업무 범위로 좁히기
사이드바에서 "실적"·"법규"처럼 범위를 골라두면 그 범위의 문서로만 검색을 좁힌다.
2
후속 질문이면 독립 질문으로 재작성
"그중 A는…" 같은 질문은 최근 대화를 참고해 그 자체로 이해되는 질문으로 다시 쓴다.
3
의미로 관련 문서 조각 찾기 + 보완
질문을 숫자로 바꿔(임베딩) 아카이브에서 뜻이 가까운 조각을 넓게 찾고, 부족하면 추가로 보완한다.
4
AI(Claude)가 근거만으로 종합
모아온 문서 조각만 근거로 답을 작성한다. 근거에 없는 내용은 "확인 필요"로 표시한다.
↓
답변 · 실적 수치와 근거 조항이 함께 제시되고, 각 문장 옆에 [1][2] 처럼 출처 번호가 붙는다. 번호를 클릭하면 원문의 정확한 위치가 열려 눈으로 재검증할 수 있다.
05

내부 + 외부 자료를 함께 쓰면

관련 법·규제·동향은 언제 어디서 새로 생길지 모르고, 그걸 전부 미리 아카이빙해두는 건 불가능하다. 이럴 때를 위한 확장이다.

1
질문창에서 자료 범위 선택
"내부 자료만" / "내부 + 외부 자료" 중 고른다. 안 고르면 항상 내부만.
2
내부 검색은 그대로 실행
§04와 동일하게 아카이브 전체에서 근거를 찾는다.
3
★ "외부" 선택 시 — 웹 검색도 함께 실행
키 없는 웹 검색(DuckDuckGo)으로 관련 페이지를 찾는다. 별도 계약·API 키 없이 동작한다.
4
근거를 이름표로 구분해 결합
내부는 [1][2], 외부는 [브라우징0][브라우징1] — 절대 서로 섞이지 않는다.
5
AI가 두 근거를 함께 종합해 답변
내부 자료와 외부 자료를 모두 참고해 하나의 답을 만든다.
실제 라이브 확인: "최근 유통산업발전법 개정 동향을 알려줘. 내부 문서에 없는 최신 정보도 찾아줘"라는 질문에, 내부 문서에 없다는 걸 스스로 인지하고 웹 검색으로 국회입법현황·법령정보센터 등 5개 페이지를 찾아 답을 구성했다. [브라우징N]을 클릭하면 사이드바에 실제 웹페이지가 그대로 열린다.

왜 필요한가

  • 새 법·규제·가이드라인이 어디서 생길지 미리 알 수 없어, 아카이브만으로는 항상 최신 상태를 유지하기 어렵다.
  • "순수 내부 자료 기반 답변"과 "내부 + 외부 이슈까지 파악한 답변"을 상황에 맞게 선택할 수 있다.
  • 답변마다 어떤 문장이 내부/외부 근거인지 항상 구분되어 표시되므로, 신뢰도를 스스로 판단할 수 있다.

07

(신규) 전사문서작성tool — 정기 문서 갱신 작성

§06은 "답변 하나"를 보고서로 만드는 것이었다. 이건 그보다 훨씬 큰 작업이다 — 작년에 완성된 문서 전체를 양식/구조로 삼아, 올해 새로 생긴 기준에 맞춰 아카이브 전체에서 근거를 찾아 문서를 절별로 다시 채워 넣는다.

1️⃣
이름 입력

어떤 문서를 만들지 정하기

예: "2026년 지속가능경영보고서", "2026년 공정거래협약 이행평가"

2️⃣
기준 문서 선택 (다중 가능)

작년 문서를 문서함에서 고른다

구조와 양식의 뼈대로 쓴다. 여러 문서를 함께 골라 하나로 이어붙일 수도 있다.

3️⃣
신규 기준/가이던스 입력

텍스트로 붙여넣거나, 파일을 업로드

파일을 올리면 그 자리에서 파싱해 아카이브에 바로 추가하고, 기준 문서와 같은 분류로 즉시 확정(같은 폴더 효과)한 뒤 본문을 읽어온다.

4️⃣
자동 처리

목차 추출 → 신구 비교 → 절별 처리

각 절을 유지(그대로) / 갱신(내용 다시 채움) / 신규(새로 작성)로 나누고, 갱신·신규 절만 아카이브 전체를 검색해 근거를 채운다.

5️⃣
결과 확인

[자료 필요] 클릭 → 근거 · 과거자료 → 다운로드

부족한 항목을 누르면 근거(신규 기준 발췌)와 과거 참고자료를 보여준다. 전체를 자료요청서 또는 HTML로 내려받는다.

이게 왜 중요한가

(1) 아카이브에 뭐가 이미 쌓여있는지 절별로 눈에 보인다 — "유지"·"갱신" 표시로 얼마나 자동으로 채워졌는지 한눈에 확인된다.
(2) 이미 있는 자료를 또 요청하지 않는다 — [자료 필요] 표시된 항목만 관계 부서에 요청하면 된다.

실제 라이브 검증

GS25 상생협력 협약서(19개 조항)를 기준으로, 반경 250m·판촉비용 70:30·디지털전환·ESG 4개 신규 기준을 입력했다.

ESG 절은 아카이브의 실제 지속가능보고서 데이터(포장재 적용률)를 찾아 채우고, 없는 부분(외부 협업사 역할분담)만 [자료 필요]로 남겼다 — "다른 목적으로 적재된 자료도 함께 활용"이 정확히 작동함을 확인했다.

분류 체계

6개 축(민감도/업무분류/사업부/문서종류/분야/태그)으로 AI가 제안하고 사람이 확정한다. taxonomy.js가 기준값의 단일 소스다.

  • 값 삭제 UI — 각 드롭다운에 삭제 버튼. 확정된 문서가 그 값을 쓰면 건수를 안내하며 차단한다.
  • 기본 정렬 — "미확정 먼저"로, 검수 화면에 들어가면 처리할 문서가 항상 위에 보인다.
  • 사업부 목록에서 전사·유통BU·정책지원팀·기타를 정리 — 실제 조직 단위(홈쇼핑BU·편의점BU·수퍼마켓BU)만 남겼다.
  • DocumentClassification.confirm() — 사람이 직접 확정하거나(검수 화면), §13처럼 이미 확정된 값을 그대로 물려받아 즉시 확정할 수도 있다.
10

인용 추적 · 후속질문 보완 로직

인용 추적

  • stream.js에서 sources.map((s,i) => ({...s, citationIndex: i}))로 모델이 쓰는 번호와 소스 배열 인덱스를 항상 일치시킨다.
  • 프론트 linkifyCitationMarkers()가 답변 텍스트의 [n]을 클릭 가능한 버튼으로 바꾸고, 클릭 시 사이드바가 정확히 그 출처로 스크롤·강조된다.
  • 같은 구조를 browsingIndex 네임스페이스로 확장해 [브라우징n](§11)도 동일하게 동작한다.

후속질문 보완 로직

  • 질의 재작성(condenseFollowupQuery): 대화 기록이 있을 때만, 최근 6턴을 참고해 LLM 1회로 독립적인 질문으로 다시 쓴다. 첫 질문이면 건너뛴다.
  • 보완 병합(mergeFollowupSearchResults): 재작성 질문의 검색이 부족하면 원래 질문으로도 한 번 더 검색해 새로 찾은 것만 덧붙인다(순서·기존 결과는 안 건드림).
11

내부 + 외부 자료 검색 (기술)

  • 검색: server/utils/webSearch — 별도 계약·API 키 없이 DuckDuckGo 결과 화면(HTML)을 읽어 제목·요약·링크를 뽑는다.
  • 인용 분리: 내부는 citationIndex([n]), 외부는 browsingIndex([브라우징n]) — 시스템 프롬프트 문자열에 직접 덧붙여 모델의 자동 번호 매기기와 충돌하지 않는다.
  • 출처 화면: [브라우징N] 클릭 시 실제 웹페이지를 iframe으로 띄운다. 6초 안에 로딩이 안 끝나면 "새 탭에서 열기"로 전환.
  • 발견·수정한 버그: DuckDuckGo 파싱 정규식이 속성 순서를 가정하고 있어 실패하는 경우가 있었다 — 순서 무관 방식으로 수정. 서버 실행 시 사내 인증서 경로(NODE_EXTRA_CA_CERTS)가 없으면 외부 요청이 전부 실패한다는 것도 재확인.
12

문서 초안 작성 (기술)

  • 2축 구조: 자료범위(answer_only/answer_plus_web) × 문서유형(basic/analysis) — 공통 뼈대 + 조건별 추가 절로 구성해 4가지 조합을 하나의 프롬프트 매트릭스로 관리.
  • 외부자료 보강 시: 답변 내용으로 검색어를 뽑는 LLM 호출 → 웹 검색 → 채팅 답변에 이미 있던 [브라우징N] 소스를 URL 기준으로 재사용·병합 → 외부 근거는 (외부 자료) 표시 + "외부 참고자료" 절로 정리.
  • 근거 부족 처리: "추가 확인 필요" 원칙 유지 — 외부 검색을 켜도 새 사실을 지어내지 않는다.
13

전사문서작성tool (기술)

목차 추출

  • extractOutlineFromBlocks() — 청크의 section_path 메타데이터로 절을 나눈다. 커버리지가 30% 미만이면(예: 구조 인식이 약한 docx) null을 반환해 다음 방식으로 넘긴다.
  • extractOutlineViaLLM() — 모델에게 원문을 다시 쓰게 하지 않고, 각 절이 "이 구절로 시작한다"는 경계 마커만 받아 원문(pageContent)에서 직접 잘라낸다 — 원문이 그대로 보존된다.
  • 기준 문서를 여러 개 고르면(다중 선택) 문서별 목차를 순서대로 이어붙인다.

신구 비교 · 절 작성

  • diffOutlineAgainstGuidance() — LLM 1회로 절마다 keep(유지)/update(갱신)/new(신규) 분류. 응답이 비정상이면 전부 keep으로 취급(잘못 지우는 것보다 안전).
  • keep 절은 검색 없이 작년 내용을 그대로 통과시킨다 — update/new 절만 performSimilaritySearch로 아카이브 전체를 검색해 근거를 채운다.
  • 근거 부족 시 본문에 [자료 필요: 설명] 마커를 남긴다(draft.js의 "확인 필요"와 같은 원칙) — extractNeeds()가 이 마커를 정규식으로 뽑아 프론트의 클릭 가능한 버튼으로 연결한다.

신규 기준 파일 업로드

  • POST /workspace/:slug/doc-regen/upload-guidance — Collector로 파싱 → Document.addDocuments()로 워크스페이스에 바로 임베딩 → 기준 문서와 같은 분류를 DocumentClassification.confirm()으로 즉시 확정(검수 대기 없음) → 읽어낸 본문을 응답으로 반환.
  • 발견·수정한 버그: content_hash는 addDocuments가 임베딩하면서 계산해 workspace_documents 행에 써넣는다 — 업로드 직후 원본 파일을 그대로 읽으면 txt 등 일부 형식에서 비어 있어, 임베딩된 행을 다시 조회하도록 수정했다.

진행 상황 스트리밍

POST /workspace/:slug/doc-regen/stream — stream-chat과 같은 SSE 패턴. outline_start → outline → plan → (section_start → section_done)×N → done 순서로 이벤트를 흘려보내, 절이 많아 시간이 걸려도 진행 화면에서 무엇이 처리되고 있는지 실시간으로 보여준다.

알려진 이슈

  • 전사문서작성tool 생성 시간 — 절마다 검색+생성이 필요해 절이 많으면 오래 걸린다. 절 단위 병렬 처리는 아직 미구현(순차 처리).
  • 웹 검색의 구조적 한계 — 키 없는 스크래핑 방식이라 대상 사이트 구조 변경에 취약(§11).
  • 초안·전사문서작성tool의 docx·xlsx 내보내기 — 버튼은 있으나 비활성. HTML만 동작.
  • 고성능 임베딩(bge-m3) 미사용 — 로컬 PC 메모리 한계로 경량 모델(e5-small) 유지 중.
  • 서버 미확보 — 팀원 개인 PC에서만 실행.
