이 파일이 NEXUS 아키텍처의 단일 기준 문서입니다. 구조·보안·운영이 바뀌면 이 파일에 반영합니다.

새 변경은 §13 변경 이력 맨 위에 추가하고, 영향받는 절을 같이 고칩니다.

저장소가 공개이므로 비밀번호 · 사내 IP · 회사 문서 이름 · 키는 적지 않습니다.

1.한눈에 보기

v27 까지는 윈도 PC 한 대에서 로그인 없이 돌았고, v28 에서 맥으로 옮기면서 아래가 추가됐습니다.

  1. 폴더 비밀번호 — 업로드하는 사람이 폴더를 만들며 비밀번호를 정하면, 모르는 사람의 검색·열람에서 그 폴더가 제외된다.
  2. 브라우저별 대화 분리 — 로그인 없이 브라우저마다 대화·스레드가 따로 보인다.
  3. 관리자 콘솔 — 관리자 비밀번호로 들어가는 별도 화면. 설정·관리 기능은 여기로 모았다.
  4. 문서 요약 — 문서마다 한두 문장 요약을 만들어 문서함에 보여 준다.
  5. 운영 보강 — 한글 폴더 이름(NFC/NFD) 처리, 시작 시 DB 마이그레이션, 테스트의 .env 오염 방지.

4.접근 제어 (v28 핵심)

4-1. 사용자 식별 — 로그인 없이 "브라우저"를 사용자로

  • 브라우저가 처음 열릴 때 임의의 ID(24바이트 난수)를 만들어 localStorage 에 저장한다 (utils/nexusClient.js).
  • window.fetch 를 감싸서 API 로 가는 모든 요청에 X-Nexus-Client 헤더를 붙인다 (스트리밍 포함). 헤더를 못 붙이는 <iframe>/링크 URL 은 ?cid= 쿼리를 쓴다.
  • 서버는 이 ID 로 "이 브라우저가 연 폴더"와 "이 브라우저의 대화"를 구분한다. 사람이 아니라 브라우저이므로, 같은 사람도 기기·브라우저마다 다른 사용자이고 브라우저 데이터를 지우면 새 사용자가 된다.
  • 쿠키를 쓰지 않는 이유: 프론트(:3000)와 API(:3001)가 다른 출처이고 서버 CORS 가 자격증명을 허용하지 않는다.
  • 사내 SSO 를 붙이면 이 ID 대신 사번이 키가 된다 (미구현, §12).

4-2. 접근 범위(scope) 계산 — server/utils/folderAccess/index.js

요청마다 한 번 buildScope() 로 계산해 AsyncLocalStorage 에 두고, 이후 모든 읽기 경로가 이것만 본다.

  • 폴더 = docpath 의 첫 구간. 루트 파일은 잠글 수 없다.
  • 비밀번호는 scrypt + 폴더별 salt 해시로 저장 (folder_locks.passwordHash). 평문은 저장하지 않는다.
  • 무차별 대입 제한: (브라우저·IP·폴더)별로 10분에 5회 실패하면 10분간 거부 (메모리 보관, 서버 재시작 시 초기화).
  • 비밀번호를 바꾸면 그 폴더의 모든 열림 기록(folder_unlocks)을 지워 모두 다시 잠근다.
  • 열림 유지 시간은 기본 8시간 (NEXUS_UNLOCK_TTL_HOURS).

4-3. 한글 폴더 이름 (NFC/NFD)

윈도에서 가져온 실적 폴더는 디스크에서 분해형(NFD), DB 의 문서 경로는 조합형(NFC)이었다. 눈에는 같아도 문자열이 달라 잠금이 이 폴더 문서에 안 걸리는 구멍이 있었다.

이제 잠금 이름 · 문서 경로 · 디스크 이름을 비교하는 모든 곳이 NFC 로 정규화한다 (folderOfDocpath, normalizeFolderName, canAccessFolder, deniedDocIds, purgeFolder 등). 디스크 작업은 실제 디스크 이름으로 한다.

4-4. 검색에서 막는 방법 — 사전 필터 + 사후 필터

server/utils/vectorDbProviders/pgvector/retrieval.js

실데이터 검증: 실적 폴더를 잠금 상태로 가정하면 밀집 검색의 해당 청크 127개, 어휘 검색의 53개가 사라지고, 열었거나 관리자면 되돌아온다.

4-6. 대화 분리

workspace_threads · workspace_chats 에 client_id 컬럼. 조회·삭제·수정은 scopeChatWhere() 가 "내 기록 + client_id 가 비어 있는 이전 기록(공개)"만 보이게 합친다. 새 기록은 현재 브라우저 ID 로 저장된다. 다른 브라우저의 스레드는 열기·삭제 모두 404. 관리자 콘솔 요청만 전체를 본다.

4-7. 생성 문서의 잠금 상속

잠긴 폴더 자료로 만든 초안·PPT·전사문서 결과를 다운로드하면 "내부생성자료"로 자동 보관되는데, 이것이 공개 폴더로 새지 않게 restrictionForSources() 가 판정한다.

근거 문서의 상황결과
정확히 한 개의 잠긴 폴더에 있음그 폴더로 옮겨 보관
서로 다른 잠긴 폴더를 섞음보관하지 않음 (다운로드는 영향 없음)
잠긴 폴더 문서인데 열 권한이 없음보관하지 않음
근거를 모르는데 잠긴 폴더를 열어 둔 상태보관하지 않음
잠긴 폴더 문서가 근거에 없음기존대로 공개 보관

4-8. 관리자와 콘솔

  • 관리자 비밀번호는 secrets/admin.env 의 NEXUS_ADMIN_PASSWORD. 서버가 시작할 때 읽는다 (index.js). 값이 없으면 관리자 기능은 꺼지고 기존처럼 모두 열린다.
  • 로그인은 /api/nexus/admin/login → access_admins 에 (브라우저 ID, 만료) 저장. 기본 30분, 콘솔을 쓰는 동안 자동 연장.
  • 프론트가 콘솔 헤더를 붙이는 곳: /nexus-admin, /settings/*(분류 검수 제외), /workspace/:slug/(settings|affinity|usage).
  • 관리자 전용 경로 차단: utils/folderAccess/adminRoutes.js 한 곳의 표(26개 규칙)로 막고, consoleGuard 가 라우터에 닿기 전에 검사한다. 대상은 /admin/*, 시스템 설정 쓰기, API 키, 이벤트 로그·전체 채팅 기록, 임베드 위젯 관리, 예약 작업, 모델 라우터, 작업공간 생성·삭제, 콘솔 API 등.
  • 일반 사용자의 평소 작업 경로는 표에 넣지 않는다. 넣으면 그 기능이 403 으로 깨진다. 이 구분은 단위 테스트(adminRoutes.test.js)가 지킨다 — 예: 검색 방식 전환·모델 선택이 쓰는 workspace/:slug/update, 임베드 위젯의 공개 stream-chat, 분류 검수.
  • 화면 쪽: AdminGate 가 설정 계열 라우트(AdminRoute/ManagerRoute/SingleUserRoute)를 감싸 로그인 안 한 접근을 /nexus-admin?next=… 로 보낸다. 세션이 만료되면 403 needsAdmin 응답을 받아 같은 곳으로 보낸다.

6.문서 요약

  • 문서 내용 앞 12,000자를 읽고 설정된 LLM 이 한국어 2문장(120자 안팎)으로 요약 (utils/summaries). 수치·고유명사를 그대로 쓰고 추측하지 않게 지시.
  • 처음 한 번: server/scripts/backfill-summaries.js (이어서 실행 가능, 동시 3개). 현재 문서 전체 완료 — 154건이 352초, 실패 0.
  • 이후: 백그라운드 작업 summarize-documents 가 15분마다 새 문서를 10건까지 요약 (동시 2개).
  • 잠긴 폴더 문서는 백그라운드에서 요약하지 않는다. 아무도 폴더를 열지 않은 상태로 내용을 LLM 에 보내지 않기 위해서다. 폴더를 열 수 있는 사람이 문서함에서 요약 만들기를 누르면 POST /classification/summary 가 그 자리에서 만든다.
  • 비용 실측(1건): 6천자 → 입력 약 7.5천 토큰 · 6.1초, 3만자 → 약 3.1만 토큰 · 9.2초. 토큰은 글자 수와 거의 1:1.
  • 표시: GET /classification/documents 가 summary 를 내려주고 문서함 목록에 문서명 아래로 보인다. 접근 불가 문서는 목록에서 이미 빠지므로 요약도 같이 가려진다.

관리자 콘솔§4-8

"추출 아카이브 범위" (사이드바 드롭다운 전체/실적/법규/대외)는 저장 폴더가 아니라 문서 종류(docType) 기준으로 채팅 검색만 좁힌다. 자료 추출 · 초안 · 통계 · PPT · 전사문서작성에는 적용되지 않는다. 사규 등 일부 종류는 어느 범위에도 없어서, 범위를 좁히면 검색에서 빠진다.

자료 추출은 저장 폴더가 아니라 업무 분류 폴더 또는 개별 파일로 고른다. 분류 전 문서는 "미분류" 폴더에 들어 있으며, 잠긴 폴더 문서는 폴더를 연 브라우저에만 나타난다. 한 번에 최대 15건.

실제로 겪은 주의점

테스트가 서버를 망가뜨릴 수 있었다. 일부 jest 테스트가 dumpENV() 를 거치며 테스트용 STORAGE_DIR 을 실제 server/.env 에 써 넣었고, 다음 서버 시작부터 임베딩 모델을 엉뚱한 경로에서 찾아 문서 업로드(임베딩)가 모두 실패했다. dumpENV() 는 이제 jest 실행 중 아무것도 하지 않는다.

증상은 서버 로그의 "native embedding model has never been run and will be downloaded".

  • 개발 서버(vite)라서 화면 코드는 저장 즉시 모든 사용자에게 반영된다. 서버 코드는 서버 재시작 후 반영된다.
  • 한글 폴더를 가져오거나 복사할 때 NFC/NFD 가 바뀔 수 있다 (§4-3). 3-verify.sh 의 "문서 경로 → 파일 확인" 이 알려 준다.

10.보안 모델과 한계

지키는 것방법
비밀번호를 모르는 사람의 검색·열람§4 (SQL 사전 필터 + 읽기 경로 점검 + 변경 차단)
사용자 간 대화브라우저별 client_id 분리
설정·관리 기능관리자 비밀번호 + consoleGuard + 콘솔 헤더
비밀번호 저장scrypt 해시(폴더), 관리자는 환경변수 (파일 권한 600, 저장소 밖)
한계 (알고 쓸 것)설명
HTTP암호화 없음. 같은 네트워크에서 비밀번호가 평문으로 오간다. 소수 인원·사내망 한정이 전제
식별은 브라우저 단위사람이 아니라 브라우저. 개별 권한 부여·회수는 SSO 이후
디스크는 암호화 안 됨맥을 직접 쓰는 사람은 문서 파일과 DB 를 볼 수 있다 (FileVault 꺼짐)
LLM 전송폴더를 연 사용자가 질문하면 해당 내용이 Claude 로 전송된다 (요약은 §6 의 규칙)
일부 경로는 범위 적용 밖에이전트 웹소켓·모바일 동기화는 헤더를 못 보내 "공개만"으로 동작하거나 별도 인증을 쓴다. 외부 API 키 경로는 공개 폴더만
관리자 전체 열람관리자는 콘솔에서 모든 대화를 본다
불필요한 포트가 열려 있음브라우저는 3000번만 필요하지만 3001(API)·8888(collector)도 같은 네트워크에 열려 있고 맥 방화벽은 꺼져 있다. 3001 로 직접 들어와도 같은 서버의 접근 범위 검사를 거치므로 우회는 아니지만, 노출 면적을 줄이려면 방화벽이나 바인딩 제한이 필요하다
시도 횟수 초기화무차별 대입 제한이 메모리 보관이라 서버 재시작 시 초기화

12.남은 과제 / 결정 대기

  1. HTTPS 적용 (사내 IT 인증서 권장). 접속자가 늘거나 기밀 자료를 보호하기 시작하면 필요.
  2. 사내 SSO 연동 → 브라우저 ID 를 사번으로 교체, 개별 권한 부여.
  3. 로그인 없는 부팅 시 자동 시작, 맥 재부팅 후 동작 확인.
  4. 항상 켜져 있는 서버(별도 PC/서버)로의 이전 검토 (맥 잠자기·메모리 한계).
  5. "추출 아카이브 범위"를 저장 폴더/분류 폴더와 일치시킬지, 정리할지 (§8).
  6. 요약 범위: 지금은 앞 12,000자. 긴 문서의 뒷부분은 반영되지 않는다.
  7. 저장소를 비공개로 바꿀지.
