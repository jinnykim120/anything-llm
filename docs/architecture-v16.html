Document Expansion LLM — 1차 프로토타입

정책지원팀의 자료 정리·검색·활용을 돕기 위해 만든 사내 문서 아카이브 + AI 질의응답 시스템. 아래 앞부분은 이 시스템이 무엇을 하는지, 어떻게 동작하는지, 어떻게 만들어졌는지를 도식으로 설명하고, 뒷부분은 이번 버전(v16)에서 실제로 바뀐 내용을 기술 문서 형식으로 기록한다.

우리가 만들고자 하는 4단계

처음 기획했던 목표는 4단계다. 지금 어디까지 왔는지 한눈에 보면 다음과 같다.

✓

1단계 · 자동 분류·적재

문서를 올리면 AI가 종류·업무·분야를 제안하고, 사람이 확인만 하면 자동으로 정리돼 보관된다.

완료
✓

2단계 · 자연어 검색·답변

말로 질문하면 관련 문서를 찾아 근거를 들어 답한다. 출처와 원문 위치까지 바로 확인 가능.

완료
●

3단계 · 문서 초안 자동 작성

검색 답변을 근거로 보고서·공문 초안을 자동으로 써준다. 사람이 수정 후 내려받는다.

4

4단계 · 모바일·웹 접근

사무실 PC가 아니어도 어디서든 접속해 검색·확인이 가능해지는 단계.

착수 전
01

이 프로토타입이 할 수 있는 것

지금 시점(1·2단계 완료 + 3단계 프로토타입)에서 실제로 쓸 수 있는 기능과 장점이다.

📥

업로드만 하면 자동 정리

문서 형태(PDF·워드·엑셀·한글 파일)를 가리지 않고 올리면 AI가 업무 분류·문서 종류·분야를 제안한다. 사람이 확인·확정만 하면 태그가 붙은 채로 아카이브에 쌓인다.

🔍

자연어로 질문, 근거로 답변

"OO 기준이 뭐야?" 같은 말로 질문하면 관련 문서를 찾아 그 내용만으로 답한다. 문서에 없는 내용은 지어내지 않고 "확인 필요"라고 표시한다.

📌

출처·원문 위치 확인

답변에는 어떤 문서, 어느 조항·페이지에서 나온 내용인지 함께 표시된다. 클릭하면 원본 문서의 해당 위치로 바로 이동해 눈으로 재검증할 수 있다.

🗂️

업무별로 나눠 보기

전체 자료를 하나로 쌓아두되, 화면에서는 전체/실적/법규/대외 같은 업무 관점으로 필터링해서 볼 수 있다.

📝

(신규·베타) 초안 자동 작성

검색으로 얻은 답변을 그대로 근거로 삼아 "보고용"·"대외기관용" 문서 초안을 만들어준다. 초안은 그 자리에서 직접 고칠 수 있고, HTML로 내려받을 수 있다. 아직 다듬는 중인 기능이다.

🛡️

사람이 마지막 확인

분류도, 초안도 AI가 제안만 하고 최종 확정·수정은 항상 사람이 한다. 완전 자동화의 오류 위험 없이 반복 작업만 줄이는 구조다.

03

질문을 던졌을 때 답변이 만들어지는 흐름

예시로 아래와 같은 질문을 던졌다고 하자. 시스템이 답을 만들어내는 과정을 단계별로 보였다.

예시 질문 · "2025년 GS리테일의 국수 출하량은? 그중 가장 많은 출하량 제품은 무엇이고, 국수 출하량이 강제되는 이유는 뭐야?"
↓
1
(선택) 업무 범위로 좁히기
사이드바에서 "실적"·"법규"처럼 범위를 골라두면, 그 범위의 문서로만 검색을 좁힌다. 안 고르면 전체 아카이브에서 찾는다.
2
의미로 관련 문서 조각 찾기
질문을 숫자로 바꿔(임베딩) 아카이브 전체에서 뜻이 가까운 문서 조각들을 넓게 찾아온다. 이 예시라면 실적 수치가 있는 문서와, 출하량 근거가 되는 법령·지침 문서가 함께 걸린다.
3
빠진 부분 보완
한 문서가 답의 핵심이라면 그 문서에서 관련된 조각을 더 끌어와, "일부만 답하고 끝내는" 상황을 줄인다.
4
AI(Claude)가 근거만으로 종합
모아온 문서 조각만 근거로 삼아 답을 작성한다. 근거에 없는 수치·기관명·결론은 만들어내지 않고 "확인 필요"로 표시한다.
↓
답변 · 실적 수치(있다면)와 그 수치의 근거가 된 법령·지침 조항이 함께 제시되고, 각 내용 옆에 "어느 문서, 어느 조항/페이지"인지 출처가 붙는다. 클릭하면 원문의 그 위치로 이동해 직접 확인할 수 있다.
위 질문은 흐름을 설명하기 위한 예시다. 실제 답변에 어떤 수치가 나오는지는 그 시점 아카이브에 실제로 어떤 문서가 있는지에 따라 달라지며, 근거 문서가 없으면 시스템은 추측 없이 "근거를 찾지 못했다"고 답한다.
04

지금까지 만들어온 과정

아이디어에서 지금 상태까지, 실제로 거쳐온 단계를 순서대로 정리했다.

작업에 쓴 도구들

개발은 전부 팀원 개인 컴퓨터에서, 아래 도구들을 조합해 진행했다. 가운데 "Orca"가 전체 작업을 조율하는 오케스트레이션 도구이고, 그 위에 AI 코딩 에이전트(Claude Code)를 붙여 실제 코드 작성·설치·테스트·문서화까지 진두지휘하게 했다.

화살표는 "이 도구가 Orca(작업 조율)로 투입되어 함께 쓰인다"는 뜻이다.

단계별 진행

💡
아이디어

정책지원팀 자료 문제 정의

사내 자료가 정리되지 않은 채 쌓이고, 필요할 때 못 찾는 문제를 해결하기로 함. "① 올리면 자동 분류·적재, ② 자연어로 검색·근거 답변, ③ 자동 문서 초안 작성, ④ 모바일·웹 접근" 4단계 목표를 세움.

🧰
작업 도구 구성

Orca + Claude Code 중심 개발 환경

전체 작업을 조율하는 Orca에 AI 코딩 에이전트(Claude Code)를 붙여 코드 작성·실행·테스트를 맡기고, 로컬 실행(Python)·버전관리(GitHub)·데이터저장(PostgreSQL) 도구를 붙여 개인 컴퓨터에서 전체 시스템이 돌아가게 구성.

🏗️
기반 확보

오픈소스 AnythingLLM을 베이스로 포크

문서 업로드·검색·채팅의 기본 골격을 처음부터 만들지 않고, 검증된 오픈소스 AnythingLLM(GitHub)을 가져와 "Document Expansion LLM"이라는 이름으로 우리 것으로 개조하기 시작.

🎨
화면 교체

사내 사용자를 위한 한국어 전용 화면

해외 오픈소스의 화면을 정책지원팀이 바로 쓸 수 있는 한국어 UI(랜딩 화면, 아카이브 사이드바, 업무별 뷰)로 교체.

🔎
검색 엔진 재구축

"질문해도 못 찾는다" 문제 해결

검색 로직에 겹겹이 쌓여 서로 충돌하던 부분을 걷어내고 다시 짬. 이 컴퓨터 환경에 맞는 임베딩 모델로 교체. 그 결과 정답 문서를 찾는 비율이 100%까지 올라감.

📚
문서 구조 파싱 정비

PDF·워드·엑셀·한글 파일 구조 인식

4가지 파일 형식 각각 제목·조항·표 구조를 읽어내도록 정비. 스캔된 이미지 문서는 "이미지 기반 문서"로 표시만 해두고(§09), 향후 이미지 인식 기능 연결 대상으로 남김.

🏷️
분류 체계 구축

AI 제안 + 사람 확정 구조

업무 분류·사업부·문서 종류·분야 4가지 축으로 AI가 자동 제안하고, 사람이 검수·확정하는 화면 구축. 이후 실제 조직 구조에 맞춰 항목을 추가·삭제할 수 있게 다듬음(§07).

📊
실측·품질 검증

실제 사내 문서 68건으로 검증

실제 문서 68건을 넣고, 정해둔 질문 세트로 "정답 문서를 찾는지", "답이 근거에 충실한지", "출처가 정확한지"를 수치로 측정. 목표 1·2를 완료로 판단할 수 있는 근거가 됨.

📝
목표 3 착수

문서 초안 자동 작성 1차 프로토타입

검색 답변을 근거로 보고용·대외기관용 초안을 자동으로 쓰고, 사람이 그 자리에서 고쳐 HTML로 내려받는 기능을 만듦. 핵심 흐름은 동작하나 생성 과정에서 간헐적 오류가 있어 안정화 작업 중(§08–09).

05

지금 필요한 것 · 지금의 한계

더 나은 성능과 실사용을 위해 필요한 자원과, 그게 없어서 지금 못 하고 있는 것을 정리했다.

필요한 자원

항목현재 상태비고
작업 환경(PC)팀원 개인 Windows PC, 메모리(RAM) 제한적구현은 돼 있어도 이 환경에서 못 돌리는 기능이 있음(아래 예시)
운영 서버미확보 — 지금은 개인 PC에서만 실행정책지원팀 전체가 실사용하려면 서버(또는 클라우드) 배정 필요
Google Gemini API미승인 · 미발급스캔된 이미지 문서·이미지 위주 PPT의 내용을 읽어내는 데 필요
Claude(Anthropic) API/CLI확보·사용 중분류 제안, 검색 답변 생성, 초안 작성까지 전부 이걸로 동작
실제 사례: 검색 품질에 더 유리한 임베딩 모델(bge-m3)이 코드에는 이미 준비돼 있다. 하지만 이 컴퓨터의 여유 메모리(~1.7GB)로는 그 모델을 안정적으로 못 돌려서, 지금은 가벼운 대체 모델(e5-small)로 낮춰 운영 중이다. "구현은 준비됐지만 이 환경에서 실행은 못 한다"의 대표적인 예다. 서버로 이전하면 원래 모델로 되돌릴 계획이다.

지금 안 되는 것 (+ 이유)

스캔·이미지 문서의 내용 인식보류
사진처럼 찍힌 문서나 이미지 위주 PPT는 지금 "이미지 기반 문서"라고만 표시되고 실제 글자 내용은 못 읽는다. 이걸 읽으려면 이미지 인식이 되는 Google Gemini API가 필요한데, 아직 발급/승인 전이라 대기 중이다.
초안을 docx·xlsx 파일로 내려받기준비 중
지금은 HTML 파일로만 내려받을 수 있다. 워드(docx)·엑셀(xlsx) 형식은 화면에 버튼은 있지만 "준비 중"으로 비활성 상태다.
초안 생성이 간헐적으로 실패조사 중
목표 3(문서 초안 작성) 기능이 가끔 생성 과정에서 오류를 내며 멈춘다. AI 실행 과정의 응답이 비정상적으로 빈 채 끝나는 현상으로, 원인을 조사해 수정하는 중이다. 검색·질의응답(목표 1·2)에는 영향이 없다.
모바일·웹 접근(목표 4)착수 전
지금은 사무실 PC의 브라우저로만 접속 가능. 목표 1·2·3에 어느 정도 안정성이 확보된 뒤 착수할 계획.
06

v16 변경 개요

v15(재구축 P0–P5, 68문서 실측 완료) 이후 붙인 변경. 분류 검수 화면의 운영성 보완 2건, 그리고 목표 3(문서 초안 작성)의 1차 프로토타입 1건.

v16-A 분류 검수 — 값 삭제 · 기본 정렬 · 사업부 정리

  • 택소노미 값(업무 분류/사업부/종류/분야) 삭제 UI 추가 — 각 드롭다운에 휴지통 버튼. 확정된 문서가 그 값을 쓰고 있으면 삭제를 막고 이유를 팝업으로 안내. 신규 DELETE /classification/taxonomy/doc-type, /axis.
  • 기본 정렬을 "최신순"에서 "미확정 먼저(그 안에서 최신순)"로 변경 — 검수 화면에 들어가면 처리할 문서가 항상 위에 보임.
  • 사업부(업무 분류 축) 목록에서 전사·유통BU·정책지원팀·기타 제거, 홈쇼핑BU·편의점BU·수퍼마켓BU만 남김. 확정된 문서 0건 확인 후 실행, 제안 상태로 남아있던 46건은 값을 비워 재분류 대상으로 남김.

07

분류 체계 정리

v15까지는 택소노미 값을 추가만 할 수 있었다. 실제 운영해보니 잘못 만든/부적절한 값을 없앨 방법과, 검수 화면 진입 시 처리할 문서가 먼저 보이지 않는 문제가 나왔다.

값 삭제

  • deleteTaxonomyValue({field, settingLabel, suggested, value}) — 기본 제공 값(suggested에 있는 값)은 삭제 불가. 확정 상태(document_classifications.status === "confirmed")인 문서가 그 값을 쓰면 건수를 알려주며 차단. 통과하면 system_settings의 커스텀 목록에서 제거 + 확정 아닌 행의 해당 필드를 비움(workType은 "기타", 그 외는 null).
  • 프론트: DocRow.jsx의 각 축 셀렉트 옆에 삭제 버튼. window.confirm → 실패 시 showToast(error, "error"), 성공 시 초록 성공 토스트 + onTaxonomyUpdated로 상위 상태 갱신.

기본 정렬

정렬 옵션에 review(미확정 먼저)를 추가하고 기본값으로 설정. 비교자: needsClassificationReview(doc)가 false인(=검수 끝난) 문서를 뒤로, 나머지는 최신순.

사업부 목록 정리

BUSINESS_UNIT.suggested에서 전사·유통BU·정책지원팀·기타 제거. 삭제 전 확인: 4개 값 모두 확정 0건, 제안(미확정) 상태로 전사 34건·정책지원팀 9건·기타 3건 존재 — status !== "confirmed" 조건으로 46건 businessUnit을 null로 정리(확정 행은 손대지 않음). 그렇게 안 하면 GET /classification/taxonomy가 "실제 쓰인 값"까지 옵션에 합치기 때문에 지운 값이 다시 새어나온다.

문서 초안 작성 — 목표 3 프로토타입

알려진 이슈

  • 초안 생성 간헐적 실패 (신규, 조사 중) — POST /workspace/:slug/draft가 가끔 claude -p exited 1로 실패한다. 실패 시 응답 JSON은 input_tokens·output_tokens·total_cost_usd가 전부 0이고 stop_reason: "stop_sequence"인데, 이는 모델에 실질적으로 아무 입력도 전달되지 않은 채 바로 종료됐다는 신호다. 검색·채팅(목표 1·2) 경로는 같은 claudecli 커넥터를 쓰면서도 안정적으로 동작하고 있어, 초안 엔드포인트 쪽 프롬프트/호출 조립 과정에 특이점이 있는 것으로 추정 — 다음 세션에서 재현·수정.
  • 이미지 기반 문서 5건 + 이미지 PPTX 1건 — v15와 동일. Gemini 비전 인입(P1d, Google API 대기)까지 본문 없음.
  • 초안의 docx·xlsx 내보내기 — 버튼은 있으나 비활성("준비 중"). HTML만 동작.
  • 고성능 임베딩(bge-m3) 미사용 — 이 로컬 PC의 메모리 한계로 경량 모델(e5-small)을 계속 사용 중. 서버 이전 시 복귀 예정(v14/v15에서 이미 기록).
  • 서버 미확보 — 지금은 팀원 개인 PC에서만 실행. 실사용 전 서버/클라우드 배정 필요.
  • nodemon 불안정 — v15에서 이미 기록된 이슈, 변화 없음. (정정: v15가 "골든셋 stale"이라 적었던 항목은 이미 같은 날 후속 작업에서 해소됐다 — 10문항으로 갱신되고 68문서 코퍼스 기준으로 재검증까지 끝났다. v15 문서가 그 갱신 이전에 쓰여 반영이 안 됐을 뿐이다.)
